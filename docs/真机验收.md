# 真机验收流程

**规则：只在真机上验收，不再用模拟器。** 模拟器的 dpi、字宽、安全区、厂商 ROM
行为都和手机不同，在模拟器上「看着对」的东西到手机上是两回事，来回折腾更慢。
（2026-11-26 起执行；此前用过的 5554 / 5556 / 5558 三台模拟器已关停。）

## 0. 环境（本机已就绪，不用重装）

| 东西 | 路径 |
|---|---|
| adb | `~/dev/android-sdk/platform-tools/adb` |
| flutter | `~/flutter/bin/flutter` |
| JDK（flutter 直接调会缺） | `~/dev/java/current` |

`adb` / `flutter` 不在 PATH 里，装 release 包时这样写：

```bash
export JAVA_HOME="$HOME/dev/java/current"
export PATH="$JAVA_HOME/bin:$HOME/dev/android-sdk/platform-tools:$PATH"

adb devices -l        # 应看到一行 OnePlus 6T（型号、序列号 1f9a34d3）
```

看不到设备 = 线没插 / 手机上没允许 USB 调试。手机端做一次：开发者选项 →
USB 调试打开 → 插线后手机上点「允许」。**别用无线调试**，本机 adb 只认 USB。

## 1. 装到手机（一条命令）

```bash
export JAVA_HOME="$HOME/dev/java/current"
"$HOME/flutter/bin/flutter" build apk --release --target-platform android-arm64
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

要点：

- **装 release 包，不装 debug 包。** debug 包在同机冷启动 ≈3.5 s、release ≈0.39 s，
  差 9 倍，体感完全不同。
- **签名钥匙钉在项目里**：`android/app/build.gradle.kts` 的 `signingConfigs.app` 指向
  `android/app/signing/smalljj.jks`（alias `androiddebugkey`，密码 `android`，自用不上架），
  debug / profile / release 全用这一把，文件已入库。所以 `adb install -r` 能直接覆盖，
  **数据库不会丢**。
- 别让环境变量决定签名：曾经因为 `ANDROID_SDK_HOME` 指到 `~/dev/android-avd`，Gradle
  在那儿另生成了一把 debug 钥匙，于是手机上报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，
  只能卸载（数据一起没）。换钥匙也是一样的后果——这块之后不能换。
- `--target-platform android-arm64` 只编手机要的那一份，比默认的胖包快。OnePlus 6T 是 arm64。
- 换机器（或换上 arm64 以外设备）才需要 `--target-platform android-arm`。

## 2. 验收看什么（当前这轮：字体统一）

冷启动到「今天」页，逐项过：

1. **体重卡两颗胶囊**：左「现在 16:04」、右「66.00 kg」——同一字号、同一字重、
   同一字族，数字高度一样；两颗胶囊等高，缝 8 dp，和下面保存键左右对齐。
2. **点开时间胶囊**：两列「时 / 分」滚轮，滚轮里的数字和胶囊上的数字一样大；
   滚一格就回写，右上「现在」一键跳回。
3. **点开体重胶囊**：左整数字、右两位小数，滚到哪格就是哪格，不出现别的字号。
4. **点日期半边开「年 / 月 / 日」三列**：`2026年` 这种带单位的格子不挤不溢出，
   「日」列到今天就停（向下拖才是往回翻）。
5. **图表刻度**：体重图的坐标数字是最小那档，不该和正文抢眼。
6. **底部导航栏**：点任意一横、进出浮层时不许上下位移；键盘弹出时也不许动。

任何一处字号和别处不一样，就把截图和位置告诉我——不要再各自 `copyWith(fontSize:)`，
改 `lib/theme/tokens.dart` 里的令牌（`test/typography_test.dart` 会拦住私自改字号）。

## 3. 出问题时怎么取证

```bash
ADB="$HOME/dev/android-sdk/platform-tools/adb"

# 崩溃 / 异常栈
"$ADB" logcat -d -t 400 | grep -iE 'flutter|smalljj|AndroidRuntime' | tail -60

# 当前页截图（直接拉成 png）
"$ADB" exec-out screencap -p > /tmp/sj_phone.png

```bash
# 数据库导出：release 包不可调试，run-as 会报 "package not debuggable"。
# 因为 debug 与 release 现在同一把钥匙，先 -r 装 debug 包（数据不动）、导完再装回 release。
ADB="$HOME/dev/android-sdk/platform-tools/adb"
export JAVA_HOME="$HOME/dev/java/current"
"$HOME/flutter/bin/flutter" build apk --debug
"$ADB" install -r build/app/outputs/flutter-apk/app-debug.apk
# 打开一次 App，让进程起来后：
"$ADB" shell run-as com.smalljj.health_app \
  cp /data/data/com.smalljj.health_app/databases/smalljj.db /sdcard/smalljj.db
"$ADB" pull /sdcard/smalljj.db /tmp/sj_phone.db      # 连同 -shm / -wal 一起读
"$ADB" install -r build/app/outputs/flutter-apk/app-release.apk
```

# 链接入口（带数值就直接落库，不弹表单）
"$ADB" shell am start -a android.intent.action.VIEW -d "smalljj://weight?kg=59.82&time=08:00"
"$ADB" shell am start -a android.intent.action.VIEW -d "smalljj://query?what=budget"
```

## 4. 交付约定

- 每轮改完：`flutter analyze` → `flutter test` → 编 release → 装手机 → 在手机上截图确认，
  四步都过了才说「这轮做完」。没跑过的检查不要写成跑过。
- 这一轮的状态（改了什么、验证到哪、还有什么没验）写在
  [`本轮实现与取舍.md`](本轮实现与取舍.md) 末尾，下一轮先读它。
