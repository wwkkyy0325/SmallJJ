# 本轮实现与取舍（自用版）

自用、不商用，所以判断标准只有一条：**这一步做完能不能当天用上**。
凡是需要外部审批、需要机型适配赌运气、或者精度没把握的东西，本轮一律不做，
只把接缝留好。

## 做了什么

| 功能 | 落地方式 | 验证 |
|---|---|---|
| 时间 + 体重 | 首屏第二张卡（热量卡下面）：**两颗胶囊平分一行，都点开滚轮选，没有输入框、不弹键盘**——左边时间（默认现在、24 小时制）、右边体重（整数 / 小数两列，25.00–300.00），选好点保存 + 撤销；`weight_entry` 只存 `measured_at` 和 `weight_kg`，同一天多次都保留、日值取均值 | 单测 + widget 测试（滚轮浮层 4 条、布局坐标 1 条）+ 模拟器与真机实测 |
| 上手资料 | 第一次打开只问三项（出生年、身高、现在体重），没有性别——应用只服务女性，BMR 固定女式；活动量/目标给起步值；其余在「我的 → 身体资料」随时改 | widget 测试 2 条 + 单测 1 条（schema 无 sex 列） |
| 体重趋势 | EWMA α=0.15，缺测按天数放大 α；图上是「原始点（淡）+ 趋势线（实）」 | 单测 5 条 |
| 每日消耗 | Mifflin-St Jeor × 活动系数；有 10 天以上数据后按能量平衡反解，7:3 混合、±150 kcal/天 钳制 | 单测 8 条 |
| 热量缺口 | `TDEE − 摄入`，单一口径；缺口 ≤25% TDEE、摄入下限 1200/1500、BMI<18.5 关闭 | 单测 4 条 |
| 每日预算快照 | `day_target` 落库，历史不被新算法改写 | 单测 1 条（改资料后旧预算不变） |
| 饮食记录 | 食物库（内置 84 条）+ 每餐条目，热量 = 每 100 g × 克数，落库快照 | 单测 3 条 |
| 食物猜算 | 「两个鸡蛋一杯牛奶」式一句话解析：只归一数量与单位，热量永远来自库条目 | 单测 9 条 |
| 经期管理 | 记录开始日 → 最近 ≤6 个周期中位数 + 标准差 → 区间 + 可信度 | 单测 6 条 |
| 健康分析 | 规则引擎 9 条规则，每条带 evidence 数字；文案本地生成 | 单测 4 条（含超预算/空数据） |
| 快捷入口（兜底轨） | `smalljj://` deep link（体重/饮食/经期/查询/撤销共 8 种写法）+ 长按图标 4 条快捷方式 + 通知栏磁贴「记体重」 + MethodChannel | adb 逐条实测 + 磁贴点击实测（见下） |

全部数据在本机 SQLite（应用私有目录），无网络权限调用、无账号、无埋点。

**体重口径**：单位 kg，保留两位小数。解析（`parseWeightInput`）、范围校验（`weightInputError`）、
归一（`normalizeKg`）都在 `lib/domain/weight_input.dart` 一处；仓库 `saveWeight` 落库前再归一一次，
所以首屏、弹层、链接、引导四条写入口的值不会差在浮点尾巴上。首屏和弹层的体重是滚轮，
一格 0.01 kg，压根不存在「打字打错位」这回事；引导页和「我的」里还是输入框，第三位小数敲不进去，
而不是先让你打完再报错。

**时间口径**：只有一个键——`measured_at`。界面默认填当前时刻，点一下开两列滚轮（时 0–23、分 0–59）改；
链接带 `time=08:00` 按给定值，不带就用现在；旧的 `slot=morning|evening` 翻译成 8:00 / 20:00，
保证已经装在手机上的快捷方式不会失效。`local_date` 由时间推出，不再由调用方单独给。

**为什么不用系统的时间弹窗**（`showTimePicker`）：它跟随系统的 12/24 小时开关，12 小时制下会多出
「上午/下午」，同一个 08:05 能被读成两个时刻；默认还是表盘，改分钟要再切键盘，两次操作才办完一件
「几点几分」的事。这里的滚轮固定 24 小时制、时和分一屏选完。

**首屏顺序**：热量卡在上、体重卡在下。热量卡回答「今天还能吃多少」，是打开就要看到的那一个数；
体重卡是「填完就完事」的动作。**「什么时候」和「多少 kg」是两颗并排的胶囊，`Expanded` 各占一半行宽**，
两颗都点开浮层选（时间是滚轮，体重是整数 / 小数两列滚轮），行里没有输入框、没有光标、没有键盘。
胶囊高度是常量 `chipHeight`，所以日期从「今天」变成「昨天」、时间从「现在 15:51」变成「16:52」（少两个字）、
体重从 `61.42 kg` 变成 `62.42 kg`，只有字变：两颗胶囊的矩形和保存按钮的矩形一个像素都不动。
填完后摘要行换成「最近 … kg」时卡片不长高，上面的热量卡不被推动
（`test/layout_test.dart` 量的是两颗胶囊 + 保存按钮的矩形，不是截图）。

## 明确放弃的（不确定 = 不浪费时间）

1. **OPPO 小布意图框架正式接入**：需要 OPPO 开放平台准入、client_id/secret、
   意图名与 serviceId 由对方下发，且官方文档把接入描述成「意图共享」——
   数据要出端，和「全本地」直接冲突。自用开发者拿不到这套资质，
   继续做只会卡在等待审核。替代方案见下节。
2. **端侧 LLM 做分析文案**：1B 模型 0.5 GB 起，中端机首字延迟和外存都吃紧，
   收益只是「措辞更自然」。规则引擎已经能产出准确、可解释、零延迟的结论。
   `profile.ai_narration` 开关保留，将来接模型只换渲染层。
3. **拍照识别食物**：自采品类训的小模型在新菜上误差可以到 2 倍，
   对热量缺口是致命的。文本解析 + 搜索 + 自建条目的准确率反而更高。
4. **Health Connect 步数**：要用户授权、各机型字段不一致、还要处理重复计数，
   本轮 TDEE 用活动系数 + 体重变化自适应校准，已经能收敛。

## 小布这条线怎么走（不需要审批的部分）

App 已经把自己注册成 `smalljj://` 的处理器。三条路任选，都不需要 OPPO 账号：

```bash
# 1) 命令行/自动化直接触发（已验证）
adb shell am start -a android.intent.action.VIEW -d "smalljj://weight?kg=59.82&time=08:00"

# 2) 长按桌面图标 → 四条快捷方式（记体重 / 记饮食 / 今天还能吃多少 / 记经期开始）

# 3) 下拉状态栏 → 磁贴「记体重」（时间取点下去的那一刻）
```

小布那条「语音说一句 → 打开链接记一笔」不通：小布没有「打开链接」这个动作，
只有「打开应用」（带不了参数），证据与替代方案见 `docs/手机助手接入.md`。

## 位置和尺寸是定死的（不是一个组件一个样）

规则只有一条：**固定组件的高度不随内容变，弹出组件的位置不随内容变**。
数值全部收在 `lib/theme/tokens.dart` 的 `AppLayout` 里，业务代码不许自己写。

| 令牌 | 值 | 管什么 |
|---|---|---|
| `fieldHeight` | 52 | 所有输入框、所有主按钮（同高） |
| `errorSlot` | 20 | 错误行：没出错也占位，出错只换文字和描边颜色 |
| `chipHeight` | 52 | 选择胶囊的高度（= `fieldHeight`，和保存按钮同高）；**宽度没有令牌**，由 `Expanded` 平分行宽，窄屏不顶出去、宽屏不留空档 |
| `popoverGap` / `popoverInset` | 6 / 8 | 浮层与锚点的缝、离屏幕边缘的最小距离 |
| `wheelRow` × `wheelRows` | 44 × 3 | 滚轮一行的高度、一屏三行（中间那行是当前值） |
| `timePopoverWidth` / `dayPopoverWidth` / `kgPopoverWidth` | 188 / 240 / 200 | 两列时:分 / 三列年月日 / 两列整数+小数；高度都是 `xs + 132 + 36 + xxs = 180` |
| `sheetMaxWidth` | 480 | 弹层最宽，超过就居中 |
| `sheetGutter` | 24 | 头部、内容、底部按钮**共用**一条左右留白 |
| `sheetTopPad` / `sheetHeader` / `sheetFooterGap` / `sheetBottomPad` / `sheetTopGap` | 12 / 48 / 12 / 24 / 40 | 弹层四段的高度与顶部最小留白 |
| `dialogMaxWidth` / `dialogInset` / `dialogAction` | 400 / 28 / 44 | 对话框宽度上限、左右留白、按钮高度 |

两个唯一实现：`lib/ui/common/app_sheet.dart`（所有底部弹层）、
`lib/ui/common/app_dialog.dart`（所有对话框）。业务代码里已经**没有**
`showModalBottomSheet` / `showDialog` 的直接调用。

### 这一轮修掉的三个真问题

1. **弹层内容顶到屏幕边缘**：`AppSheet` 只给头部和底部按钮加了左右留白，内容段没有，
   所以弹层里的输入框、保存按钮贴着 0 和 1080。现在三段共用 `sheetGutter`
   （实测标题、chip、保存按钮左边缘都在 x=63 = 24 dp），`test/layout_test.dart`
   加了三条坐标断言锁住它。
2. **「添加」按钮文字被裁成两行**：记饮食弹层底部那个按钮宽 76 dp，而 `FilledButton`
   默认左右内边距就吃掉 48 dp，剩 28 dp 放不下「添加」两个字，上下各裁掉一点。
   现在去掉默认内边距、宽度给到 84 dp，实测 `[796,2001][1017,2138]` 一行显示完整。
3. **系统选日期弹窗是英文的**：界面写「称重日期」，日历里却是 `Thu, Nov 26` / `November 2026` /
   `Cancel` `OK`，一周从周日开始。原因是 `MaterialApp` 没设 locale，也没挂
   `flutter_localizations`。现在 `locale: zh_CN` + 三个 Global delegate。
   后来整个系统日历被自绘的三列滚轮换掉（见上面位置表），这套 localizations
   留着的理由是 Material 的其他文案（如遮罩的语义标签）也跟着变成中文。
   这是本轮唯一新增的依赖（`flutter_localizations`，SDK 自带）。

### 需要说清楚的一件事：两个模拟器的应用数据被清过一次

`adb install -r` 报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（旧包签名和新构建不一致），
只能 `pm uninstall` 再装；`pm uninstall -k` 留数据那条路在 PackageManager 里留下了
半删状态（`dumpsys package` 显示 `pkg=null`），装新包仍然失败。所以
emulator-5554 / 5558 上的记录被清空，首屏回到引导页——上面的引导页实测就是这么来的。

## 待人工确认

- 摄入下限 1200/1500 kcal：这是常见保守阈值，不是指南原文，界面上已注明是钳制值。
- 食物库 84 条数值是公开参考值取整，个体差异大，用户可自建覆盖。
- 经期预测的「可信度」是启发式（样本量 + 标准差），不是统计置信区间。
