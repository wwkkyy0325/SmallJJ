# 手机助手接入：哪层通了、哪层根本不通

结论先放前面，因为前几轮的文档在这件事上说错了。

1. **协议这层是对的，而且已经实测。** `smalljj://` 注册成 VIEW + BROWSABLE，MainActivity
   `singleTask` + `onNewIntent`，9 种写法全部落到数据库里（验证记录见文末）。
2. **「对小布说一句话 → 直接进 App 记一笔」这条路不存在。** 小布没有给第三方
   「打开某个链接 / 执行某个 App 动作」的能力，只有「打开应用」这一档（launch intent，
   带不了参数）。
3. 所以之前写在 README 和 App 内「小布 / 快捷指令」页的那套
   「小布指令 → 新建指令 → 添加动作 → 打开链接 → 粘 scheme」是**错的**，
   已从两处删掉。不是配置没调对，是那个动作在小布里不存在。

## 一、小布到底给了什么

| 能力 | 能不能带参数进 App | 依据 |
|---|---|---|
| 「打开 SmallJJ」 | 不能，只是 launch intent | 系统级「打开应用」动作，任何应用都有 |
| 小布指令（`com.coloros.shortcuts`） | 不能 | 动作集里只有系统开关、打开应用一类；没有「打开链接 / 打开网页」。社区想用它触发自定义 URL Scheme 或 Activity，只能靠 Xposed 模块 hook（OplusKeyHook、侧键功能模块），有公开接口就不需要 hook 了 |
| 小布建议 / 流体云 | 方向相反，是 App 把数据推给 OPPO 云出卡 | OPPO 开放平台「意图框架 / 意图共享」接入指南：要 client_id/secret、serviceId、云侧账号关联 |
| 小布技能平台 | 能，但要云侧 webhook + 审核 | 官方技能开发平台，不是端侧 Intent |

旁证：ColorOS 设计总监 2024-10-09 回应「小布能不能像 iOS 快捷指令」时说的是
「这个需要各个应用提供相对标准的接口供指令组合使用，确实没有 iOS 那么的标准化」。
也就是说 iOS 那套 Shortcuts 动作注册、Android 这侧在 ColorOS 上没有对应物。

## 二、真正可用的一步入口

都在本机（emulator-5558 / Android 15）点过：

| 入口 | 操作成本 | 实现 |
|---|---|---|
| 首屏体重卡（热量卡下面） | 打开 App → 点一下时间胶囊 / 体重胶囊，滚到要的那格 → 保存 | 主路径，`today_page.dart` + `lib/ui/common/weight_entry.dart`（两颗胶囊平分一行，没有输入框、不弹键盘） |
| 通知栏磁贴「记体重」 | 下拉 → 点一下 | 新增 `WeightTileService`，时段按钟点猜（<11 早上 / ≥17 晚上 / 其余任意） |
| 长按桌面图标 | 长按 → 点快捷方式（5 条） | `res/xml/shortcuts.xml` 静态快捷方式 |
| 任意能打开链接的地方 | 一次跳转 | `smalljj://`，浏览器/扫码/笔记/adb 都行 |

磁贴是目前最省事的一条：不依赖任何助手、不依赖桌面、锁屏下拉就够。

## 三、要「一句话记体重」还缺什么

按可行性排序：

1. **OPPO 意向框架准入**（唯一官方路）：开放平台申请 client_id/secret，平台审核后下发
   意图名与 serviceId，走「意图调用」让端侧执行。自用拿不到审批；「意图共享」那条还要
   把数据推到 OPPO 云出卡，和「数据只留本机」直接冲突。
2. **小布技能平台**：云侧 webhook + 审核，等于给自用 App 建一个云服务，比现在重得多。
3. **换 GMS 设备走 App Actions**（`actions.intent.*`）：国行 ColorOS 没有 GMS，不适用。
4. **不用语音，把点击降到一次**：本文第二节那几条，本期做完了磁贴。
   日常「早上称完、晚上称完」各一次点击，已经不比语音慢多少。

结论：在拿到 OPPO 准入之前，不要在任何文档里承诺「小布语音记体重」。

## 四、验证记录（2026-11-26，emulator-5558 / AVD SmallJJ / API 35）

`adb shell am start -W -a android.intent.action.VIEW -d '<uri>'`，逐条打，然后翻数据库：

> 下表是**当时**（体重还带 `slot` 时段槽）的实测原样记录。之后时段槽已去掉，体重只有
> `measured_at`：现在用 `time=HH:mm` 给时刻，不带就取当前时间；`slot=morning|evening`
> 仍兼容，翻译成 8:00 / 20:00。以《本轮实现与取舍》的口径为准。

| 链接 | 结果 |
|---|---|
| `smalljj://weight?slot=morning&kg=60.42` | 直接落库：`weight_entry(morning, 60.42)`，首屏显示「已记 今天早上 60.42 kg（原 60.42）」+ 撤销，预算 1362→1366 |
| `smalljj://weight?kg=60.9` | 12:08 落 `other` 槽，`weight_entry(other, 60.9)` |
| `smalljj://weight/61.2` | 路径写数值，覆盖同槽：`weight_entry(other, 61.2)` |
| `smalljj://record?slot=evening` | 弹层，时段已选「晚上」，输入框预填 60.90 |
| `smalljj://food?meal=lunch&text=两个鸡蛋一杯牛奶` | `meal_entry(lunch)` + 鸡蛋 100 g / 144 kcal、牛奶 250 g / 135 kcal |
| `smalljj://food` | 切到饮食页（热启动也进得去，上一轮修的监听器注册表生效） |
| `smalljj://query?what=budget` / `period?action=status` / `today` | `Status: ok`，不写数据 |
| `smalljj://undo` | 命令行漏跑（heredoc 吃掉了最后一行），未验证 |

`day_target` 随后按新的体重重算：`tdee 1831.84 / 预算 1373.88 / 缺口 457.96`。
